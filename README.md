Detecting and Investigating Credential Attacks in Microsoft Sentinel


**Role:** Tier 1 SOC Analyst (project)
**Tools:** Microsoft Sentinel, KQL, Azure Arc, Windows Security logs, MITRE ATT&CK
**Scope:** Detection rules, alert triage, incident investigation, escalation decisions, incident reporting

## Overview

This project shows how I work an alert from detection to closure. Windows endpoints in an Active Directory domain send Security logs to Microsoft Sentinel. I wrote detections for credential and privilege attacks, simulated those attacks, then triaged and investigated the alerts as I would in a SOC.

The environment is supporting infrastructure. The analyst work is the focus: what fired, how I investigated, what I decided, and what I would recommend.

## Triage and escalation

For each alert I ask:

1. Is the account privileged?
2. Did any attempt succeed?
3. Is the source internal or external, and is it normal for this host?
4. What happened after the logon?
5. Is this expected activity (admin task, service account, lab testing)?

**I escalate to Tier 2 when:** a privileged account is involved, a successful logon follows repeated failures, audit logs were cleared, persistence is indicated (new accounts, group changes), or more than one host is affected.
